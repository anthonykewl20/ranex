# ADR-025 — A/B/C contract freeze

**Status:** accepted
**Date:** 2026-08-16
**Decision-makers:** repo owner
**Slice:** `docs/slices/SLICE-029-abc-contract-freeze.md`

## Context and Problem Statement

ADR-017 requires three non-self-referential, digest-bound approval levels, but
does not freeze their bytes, parse profile, closed field shapes, or error
precedence. A producer could otherwise reinterpret approved semantics, sign a
different domain, or let JSON parser differences alter an identity.

## Decision Drivers

- A has approved semantics only; generated bytes belong solely in B.
- Every identity digest has one lower-case `sha256:` grammar and canonical bytes.
- Parse ambiguity must fail before closed-shape validation.
- C must bind all ADR-017 approval context with a detached Ed25519 signature.
- Error codes and their precedence are committed data, not implementation prose.

## Considered Options

1. Strict JSON, code-point canonical bytes, DSSE PAE, and closed A/B/C: chosen.
2. RFC 8785 canonicalization: rejected; UTF-16 ordering conflicts with `canonical.py`.
3. JSON Schema runtime validation: rejected; it adds dependency and hides order.
4. Ad-hoc signing prefixes: rejected; PAE is a specified byte framing.

## Decision Outcome

`spec-packet-v1`, `generated-artifact-manifest-v1`, and
`approval-envelope-v1` are closed JSON payloads. Raw bytes are UTF-8 without a
BOM or normalization, parsed with duplicate, surrogate, float, non-plain-
integer, and unsafe-integer rejection before shape validation. Canonical output
uses Unicode code-point key order, compact UTF-8 JSON.

All payload signatures cover DSSEv1 PAE bytes. C carries detached `key_id` and
signature; `key_id` is a lookup hint, never authorization. `time_window` is
journal sequence order, not wall time. The schemas define revocation and batch
liveness vocabulary; journal APIs remain deferred.

### Consequences

- `sha256:` identities bind canonical payload bytes and PAE domain type.
- A names semantics, scope, answers, outcomes, non-goals, provenance, and IDs.
- B binds every protected artifact byte, invocation, values, controls, and exemptions.
- C binds A+B, subject/base, signer context, nonce, predecessor, capabilities,
  and base/policy/generator/harness profiles.
- The committed registry selects deterministic `E-ABC-*` failures by precedence.
- Registry `check_order` is the canonical parser check order: input type, BOM,
  UTF-8, malformed escape, surrogate, then JSON and subsequent declared checks.
- Specification IDs are case-sensitive exact matches: no trimming or Unicode
  normalization occurs, and blank or whitespace-only IDs are refused.
- JSON Schema expresses portable scalar constraints; `not_before <= not_after`
  is pinned in vectors because draft 2020-12 has no portable cross-property
  comparison keyword.

### Confirmation

`tests/contract/test_specification_abc_v1.py` consumes frozen vectors for byte
canonicalization, digests, parser rejections, closed schemas, tampering, PAE
domain separation, nonce reuse, and detached signature verification. The docs
discipline suite checks this decision's prior-art evidence.

## Improvements on the prior art

1. DSSE PAE is retained but payload type is an explicit A/B/C domain boundary.
2. JCS escaping insight is retained while code-point ordering is frozen in vectors.
3. Closed shapes include approval authority context rather than envelope metadata alone.
4. A registry makes error selection inspectable and stable across Python and TypeScript.

## Architecture surface

Add three schemas, a registry, vectors, and `foundation.specification_abc`.
The module has pure parse/canonicalize/digest/PAE/validation/signature helpers;
only loading the supplied registry bytes is I/O-like. No journal, CLI, harness,
grant, lifecycle, or admission path changes in this slice.

## Scope and threat delta

This removes ambiguity in the future approval artifact boundary: parser
smuggling, signature type substitution, incomplete approval context, generated
hashes in A, and unrecorded error precedence. It does not implement authority,
journal revocation, liveness enforcement, or effect admission.

## Quality attributes

| characteristic | scenario | measure |
|---|---|---|
| Integrity | payload type swap | PAE signature verification fails |
| Portability | non-BMP keys | frozen code-point vector bytes match |
| Auditability | malformed input | registry-selected `E-ABC-*` code |

## Reversibility

Door: two-way

v1 remains immutable. A later version can add a new payload type and registry;
it cannot silently reinterpret a v1 digest, signature, or parser result.

## Sad paths

| # | Failure | Required behaviour |
|---|---|---|
| 1 | UTF-8 BOM or invalid UTF-8 | parser refusal before shape checks |
| 2 | duplicate object member | parser refusal with registry code |
| 3 | lone surrogate | parser refusal with registry code |
| 4 | float, exponent, `-0`, or unsafe integer | parser refusal with registry code |
| 5 | noncanonical input bytes | refusal after parsing, before identity |
| 6 | generated digest appears in A | closed A shape refusal |
| 7 | omitted protected B artifact | closed B shape refusal |
| 8 | unknown version or extra field | closed shape refusal |
| 9 | wrong PAE payload type | domain substitution refusal |
| 10 | reused nonce | anti-replay refusal in supplied nonce set |
| 11 | invalid/tampered detached signature | signature refusal |
| 12 | journal predecessor absent where future API requires it | schema permits null only; API is deferred |

## Test strategy

`tests/contract/test_docs_discipline.py` validates this ADR's cited and tracked
prior art. Vectors encode exact raw inputs and goldens. Positive A/B/C values assert
canonical bytes and recorded digests. Negative partitions assert registry codes,
including duplicate members and raw lone-surrogate cases encoded outside JSON.
Tests recompute vector digests, change B and C context independently, and verify
a good detached Ed25519 signature before tampering it.

## Code review checklist

- Is validation order parser, canonicality, version/domain, then closed shape?
- Are all identity fields strict lower-case `sha256:` digests?
- Is PAE byte exact and length measured in UTF-8 bytes?
- Does C include every ADR-017 envelope field and all capability bounds?
- Are errors loaded from registry data rather than inline code constants?
- Are A and B free of each other's forbidden responsibility?

## More Information

Vendored bytes prove bytes were obtained, not that they came from the cited URL.
The slice deliberately freezes vocabulary only for journal-order time, chained
revocation rows, and one-live-batch `(subject, base)` liveness; later slices
extend the journal and grant lifecycle.
