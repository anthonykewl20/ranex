# ADR-032 — real-e2e suite framework: prereqs, goldens, subprocess coverage, one proof entrypoint

**Status:** accepted
**Date:** 2026-08-19 (revised same day — two-panel remediation; revised again same day — arbitration-confirmed declaration-grammar scheme; review records in More Information)
**Decision-makers:** repo owner
**Slice:** n/a — no slice FILE is open; issue #35's `in-progress` label is the standing claim rule firing at Phase-0 start (this ADR is that claimed Phase-0 work), and the SLICE-055 file itself opens at SPEC PRD only after this ADR is accepted, per tracker #33 phase order

## Context and Problem Statement

Milestone 4 (tracker #33; MAP §0.24/§0.30 record the owner's build order) binds every slice to a universal alignment rule: every e2e runs real toolchains over real subjects with independently re-checkable outputs, with traced runs where applicable on the ADR-031 substrate. Issue #35 (https://github.com/anthonykewl20/ranex/issues/35) freezes the input contract this ADR records: a prerequisite library, golden-transcript conventions, a subprocess coverage harness, and one documented full-suite entrypoint whose captured run is the milestone's proof artifact.

The real-e2e layer today is a set of hand-built spines, each sound and each alone. `tests/e2e/test_gating_real_suite.py` drives ordered stages over a real clone of this repository with a `Session` object whose `reach`/`block`/`require` discipline already treats absence as failure and skips as named declarations — the clone's own CLI code judges the clone, exactly the construction this frame generalizes. `tests/e2e/test_run_produces_evidence.py` freezes the suite-manifest mechanics. `tests/integration/test_slice017_native_launcher.py` probes host capability through limitation functions. But every one of those files re-implements prerequisite probing by hand — `pinned_resolver` and `network_available` in one place, the qualification limitation probe in another, `RANEX_SIGNING_KEY` checks in a third — and none of them has golden transcripts, subprocess coverage, or a single entrypoint.

SLICE-056 onward each need exactly this frame — declared prereqs, a golden to diff against, coverage that sees their subprocess spines, and one command a human can run — and the milestone's definition of done (coverage of `src/ranex` measured and reported, every gap closed or risk-accepted in writing, a captured green run at a pinned commit) cannot be assembled from per-file improvisation. This ADR is the frame. It ships no per-feature real tests: the family slices own those, and this slice builds the frame they slot into.

## Decision Drivers

- Real toolchains, real files, independently re-checkable outputs only; synthetic fixtures support, never close (issue #35 closure boundary).
- Every skip carries a machine-greppable named reason and is declared; an undeclared skip fails the entrypoint — absence blocks, never silently greens.
- No new pytest markers registered: `--strict-markers` is held; gating uses the fixture/skipif convention only.
- The manifest discipline stands: `suite freeze` owns test-ID registration; framework-added IDs round-trip without hand edits.
- Determinism: identical runs diff clean against goldens; a sabotaged output diffs dirty.
- Coverage of `src/ranex` measured across subprocess CLI runs — the hook must survive into every child environment the frame wires, vendored-clone children included; hard-killed (SIGKILL) children are a documented blind spot the threshold accounts for.
- Dependency policy: the runtime graph stays three packages; coverage.py is already a pinned dev dependency — the frame adds nothing.
- Traced runs ride the ADR-031 substrate, default off, inherit its verdict-neutrality proofs, and never reach a governed or observed command.
- Claims stay inside what frozen code can deliver: an enforcement this repo's frozen kernel cannot support is withdrawn and re-homed inside the frame's own surface, never promised twice.

- Rejected: https://github.com/microsoft/playwright — the strongest golden and auto-wait machinery in the field, but browser-lane only: it would drag a pinned browser download into a suite whose journeys are CLI and toolchain subprocesses, and its goldens are DOM/snapshot-shaped where this program needs text and wire-shaped transcripts.
- Rejected: https://github.com/tox-dev/tox — it orchestrates environments rather than assertions: no prereq-reason registry, no golden comparison, no skip-declaration discipline, and it would interpose a dependency layer between the operator and the single entrypoint this program must document honestly.

## Considered Options

1. Keep per-file hand-built spines; each family re-implements probing and skipping exactly as the gating-real-suite file does today. Rejected: SLICE-056 onward would each clone the same boilerplate, and the milestone's assembled proof — one entrypoint, one coverage report over subprocesses, one artifact — cannot be glued together from ad-hoc per-file skips.
2. Adopt an external harness (pytest-testinfra, Playwright, tox). Rejected per the prior art: wrong lanes, dependency growth, and none carries a skip-reason ledger, golden comparator, or subprocess coverage in the shape this program freezes.
3. A pytest plugin with custom markers (a `real` marker registered in pyproject). Rejected: the frozen configuration holds `--strict-markers` with no new registrations, and plugin machinery hides the entrypoint's behaviour from the review surface the milestone depends on.
4. A thin in-repo framework on the existing pytest tree: a probe library consumed by module-scoped skip fixtures, committed `.out` goldens with one deterministic normalizer, a sitecustomize-based subprocess coverage harness wired through the existing coverage.py dev dependency, and one documented entrypoint that tees transcript plus coverage report and cross-checks observed skips against the committed manifest in both directions. Chosen — revised 2026-08-19: the local-server fixture is deferred out of this slice, and the skip cross-check moved from freeze time (undeliverable there) to entrypoint time.

## Decision Outcome

In the context of milestone 4's universal real-toolchain rule and issue #35's frozen contract, facing a real-e2e layer of isolated spines, we chose a thin in-repo framework — probes, goldens, subprocess coverage, one entrypoint — that generalizes the existing clone-judges-clone construction rather than replacing it, accepting that the frame itself owns no per-feature tests and that goldens add a standing maintenance surface.

- Prereq library (`tests/e2e/_prereqs.py`): six frozen lazy probes — `pinned_resolver`, `network_available`, `signing_key`, `harness_fork`, `openrouter_key`, `qualified_host` — each returning exactly an (ok, reason) pair; module-scoped skip fixtures consume them, so every skip is machine-greppable by reason. A probe is lazy (evaluated when a consuming fixture first asks, git's `test_lazy_prereq` model) but never process-global truth: each consuming module-scoped fixture re-evaluates at its own setup, so a mid-run capability flip cannot serve a cached lie across test boundaries — git's weakness is refused, and a probe that errors is a loud failure, never a skip.
- Declared skips: the existing manifest is the ledger — every expected skip is declared in `governance/suite_manifest.json` through `suite freeze`'s TEST_ID=REASON form (mechanics already frozen by `tests/e2e/test_run_produces_evidence.py`). Freeze-time surfacing of a stale declaration is withdrawn: `suite freeze` is outcome-blind by frozen design (`freeze_manifest` freezes only the observed ID set — "test outcomes never enter the manifest"; `_validate_manifest` checks shape only; declared skips are written verbatim), so catching "declared but precondition present" there would amend frozen kernel behaviour outside this slice's ownership. Enforcement lives at entrypoint time, inside the frame's surface: the documented entrypoint cross-checks the observed junitxml skipped IDs and their machine-greppable reasons against the committed manifest and exits nonzero on (a) an observed skip with no declaration, (a′) a declared-and-observed skip whose reason drifted from its declaration — an exact string comparison naming both strings — and (b) a declared skip that did not occur when its declaration is probe-backed; the frame's probe/fixture contract tests separately refuse probe-says-present-but-fixture-skipped, so a stale declaration cannot survive a run either. Revised same day by the arbitration-confirmed declaration-grammar ruling (issue #35): every declaration carries exactly one of two grammars — `ranex-prereq:<probe>: <prose>` (HARD tier: a context-independent condition one of the six frozen probes verifies live, both directions) or `ranex-context:<context>: <prose>` (INFORMATIONAL tier: the declaration names the context it belongs to — hermetic-freeze, host-capability, operator-action; reported in the context-mismatch list, never hard); unmarked prose is refused by the frozen lint. Basis: the single-grammar mandate would hard-fail legitimately context-bound declarations — the plugin_lock harness-fork skips are absent in the hermetic freeze and present-and-running on the canonical entrypoint host — the multi-context manifest reality the direction-(b) scope ruling already recorded.
- Goldens (the PostgreSQL model): a family journey compares its normalized transcript against committed goldens under `tests/e2e/expected/<family>.out`; normalization is one centralized deterministic mask — never per-test or per-family filter lists — whose exact ordered grammar is frozen as: digests to <DIGEST>, absolute paths to <ABS-PATH>, timestamps to <TIMESTAMP>, durations to <DURATION>, chained SIDs (the frozen component shape `<yyyymmdd>T<hhmmss>.<frac>Z-<host>-<process>` joined by slashes) to <SID>, PIDs to <PID>, ephemeral ports to <PORT>, then relative paths to <REL-PATH>, applied in exactly that order by one audited function; comparison is byte-exact, and on mismatch the failure emits the full unified diff of the first differing hunk with no truncation; the grammar freezes with this slice's contract tests behind positive fixtures (each volatile class normalizes — a golden recorded from one live value of a class diffs clean against a run producing a different live value of that same class) and negative fixtures (meaningful values — exit codes, verdict words, gate names — stay discriminating, and the sabotage red control still diffs dirty); the per-family golden files freeze at SPEC PRD with their family slices.
- Sabotage controls: every golden carries a red control — mutate the expected bytes and the comparator must diff dirty — this repo's red-first discipline applied to goldens; refresh-by-copy (PostgreSQL's sanctioned workflow) is never sufficient to merge, and a refreshed golden without a passing red control is a review refusal.
- Local deterministic services: deferred out of this slice by panel demand — no server fixture, no port binding, no conftest service abstraction ships here; the curl loopback model (vendored above) is recorded research evidence for the first family slice that declares a service journey — the provisioning family, likely SLICE-058 — which will bring the in-process stdlib server, ephemeral-port binding, and masked <PORT> tokens with it; this frame's only network-adjacent behaviour is the <PORT> class in the frozen normalizer grammar and the probes that declare network absent or present.
- Subprocess coverage (the coverage.py pattern): `pyproject.toml` gains a `[tool.coverage]` run/report block — `source=src/ranex`, `parallel=true`, a fail-under threshold; `tests/e2e/coverage/sitecustomize.py` calls `coverage.process_startup()` when `COVERAGE_PROCESS_START` names a config. The hook must survive into every child environment the frame wires: frame wiring APPENDS the hook directory to the child PYTHONPATH — never replaces it away; the canonical spine's `ranex()` at `tests/e2e/test_gating_real_suite.py:260` replaces PYTHONPATH with `<clone>/src` and runs children with `cwd=<clone>`, which is exactly how a hook is silently lost, and the frame's wiring is the correction — sets `COVERAGE_PROCESS_START` to an absolute config path, and sets `COVERAGE_FILE` to one absolute shared base (`.local/ranex-e2e/coverage/.coverage`, under the ignored `.local/*` home) so every process's `parallel=true` suffix file (`.coverage.<host>.<pid>.<rand>`) lands in that one directory — those suffix names match no existing ignore pattern (`.gitignore` names `.coverage` and `coverage.xml` exactly), so the ignored home is what keeps them from dirtying a freeze tree or scattering across clone working directories, and the entrypoint's post-run sweep of that directory is load-bearing freeze hygiene: no stale input ever enters a later combine. Children hard-killed by SIGKILL are an accounted, reported blind spot the threshold absorbs; loud no-data-file detection is scoped to sitecustomize-absence in frame-wired children only — children the frame does not wire (the frozen spine's own hookless clone children) are expected to produce no data, are reported as unmeasured, and must not false-alarm, inverting coverage.py's silent no-op exactly where the frame has promised a hook.
- Traced runs: the ADR-031 substrate rides every journey — the entrypoint optionally sets `RANEX_TRACE`/`RANEX_TRACE_EVENT` to a target outside every governed root; verdict-neutrality is inherited from the substrate's own invariance proof; trace variables never reach a governed or observed command, per that ADR's propagation boundary. One mandatory joint contract case binds trace and coverage at a real subprocess (Confirmation): a traced, coverage-measured CLI child must produce its permitted out-of-governed-root trace artifact, preserve verdict neutrality and RANEX_TRACE* stripping at every governed/observed boundary, and still contribute its target lines to the combined report — the in-process seam proofs alone do not bind the two subsystems together.
- Entrypoint and proof: one README-documented command (exact invocation, env vars, expected duration budget) runs the real suite with coverage wired, tees transcript plus coverage report to the probed-writable artifact home — the pre-run writability probe fails loudly before a single artifact is written — and exits nonzero on any hard skip-ledger finding against the committed manifest: an observed-but-undeclared skip, a declared-vs-observed reason drift (exact string comparison naming both), or a probe-backed (`ranex-prereq:<probe>:`) declaration whose skip did not occur — each finding naming the test ID and reason(s); context-bound (`ranex-context:<context>:`) declarations whose tests ran are the informational context-mismatch list, names plus count, exit 0. The entrypoint run is itself the milestone's proof artifact — a real invocation transcript and a real coverage report a human can read at a pinned commit.

### Consequences

- Good: SLICE-056 onward slot into one frame — declared prereqs, goldens, subprocess coverage, one proof entrypoint — instead of re-implementing the spine per file.
- Good: the milestone's definition of done becomes demonstrable — coverage measured and reported per file and line, skips named and declared, a captured green run posted as an artifact.
- Good: the existing spines keep their behaviour; the frame is extensions only, so their frozen contracts stay green untouched.
- Bad: goldens are a standing maintenance surface — every intentional output change is a deliberate golden edit plus a red control, slower than refresh-by-copy and the deliberate price of not baking regressions into goldens.
- Bad: the fail-under threshold is a moving number — it rises as real suites grow and must be re-derived, not guessed, whenever a family lands; too tight fails honest runs, too loose measures nothing.
- Bad: the entrypoint adds a real wall-time budget to every proof run; the README states it and the artifact shows it.
- Bad: parallel coverage data files demand cleanup discipline, and combine idempotence must be stated honestly — installed coverage (7.15.3) deletes input data files on combine unless `--keep` is passed, so the first draft's "a second combine is a no-op" is false and withdrawn; idempotence here means repeated `coverage combine --keep` over retained immutable inputs produces an identical combined data file and report, and that is the tested property.
- Bad: the artifact transcript is operator-visible output — any future test that echoed key material would leak it into the artifact, so the transcript stays subject to the suite's no-secret-echo rules.

### Confirmation

Future frozen tests, named in prose here and spelled by path in Architecture surface because they do not exist yet and freeze red at SPEC PRD before implementation:

- The prereq-gate contract test — probe honesty (each probe's skip reason fires exactly when its precondition is absent; a probe reporting present while its consuming fixture skips is refused — the stale-declaration guard that freeze time cannot provide); no new pytest markers registered; module-scope re-evaluation across test boundaries.
- The real-suite-entrypoint contract test — artifact teeing and pre-run writability probe; the both-direction manifest cross-check (an observed-but-undeclared skip, a probe-backed declared-but-not-observed skip, and a declared-vs-observed reason drift each exit nonzero naming test ID and reason(s); context-bound declared-not-observed skips are the informational list, never an exit condition); hook reachability (a frame-wired child, vendored-clone wiring included, keeps the hook dir appended to its PYTHONPATH with absolute `COVERAGE_PROCESS_START` and one absolute shared `COVERAGE_FILE` — replacement is refused); sitecustomize-absence loud failure scoped to frame-wired children only — named per child through the run's child ledger — with the spine's hookless children reported unmeasured and never alarming; combine idempotence as repeated `coverage combine --keep` over retained immutable inputs yielding identical data and report; golden normalizer determinism, the positive fixture per volatile class, the negative fixture keeping meaningful values discriminating (test nodeids included — which file failed is verdict meaning), and the sabotage red control; manifest round-trip of the framework's own test IDs through `suite freeze` without hand edits; and the mandatory joint trace+coverage case — one real traced CLI subprocess with coverage enabled must produce its permitted out-of-governed-root trace artifact, preserve verdict neutrality and RANEX_TRACE* stripping at every governed/observed boundary, and contribute its target lines to the combined report.

Existing suites already guard adjacent boundaries — the docs-discipline contract governs this ADR's own citations and vendored evidence, the gating-real-suite e2e holds the spine's skip discipline, the run-produces-evidence suite freezes the (outcome-blind) manifest mechanics, and the trace schema/invariance contracts freeze the substrate the joint case binds in. ## Improvements on the prior art

- A named skip ledger where git counts skips: every reason is machine-greppable and cross-checked against manifest-declared expected skips, and an undeclared skip fails the entrypoint — git reports how many, Ranex reports which and why, and absence blocks.
- No cached prereq lie: probes re-evaluate at each consuming module-scoped fixture, so a capability flip cannot serve a stale answer across test boundaries; git's process-global lazy cache is refused.
- Red controls on goldens where PostgreSQL refreshes by copy: mutate-the-expected must diff dirty before a golden is accepted, so an implementation regression cannot enter a golden through the sanctioned workflow.
- One centralized deterministic mask where PostgreSQL keeps per-test sed lists: the ordered grammar (digests, absolute and relative paths, timestamps, durations, chained SIDs, PIDs, ephemeral ports) is a single audited function; the churn class a forgotten filter creates is designed out, and over-masking is a reviewed golden edit, never a comparator hack.
- The curl loopback model recorded, not shipped: this revision defers the server fixture to the family slice that declares a service journey, so the frame carries no machinery it cannot yet exercise — the in-process stdlib server design travels as vendored evidence plus this paragraph, nothing more.
- Loud failure where coverage.py silently no-ops: a frame-wired child producing no parallel data file is detected and reported — the harness distinguishes measured-zero from never-measured for exactly the children it promised the hook, which upstream cannot and from which the spine's unwired children are exempt.
- (ok, reason) pairs in one library where moby returns bare bools to every call site: the reason travels with the decision, so the ledger, the skip message, and the entrypoint grep all name the same precondition; a probe error is a loud failure, not a skip.

## Architecture surface

No port, no adapter, no kernel code: the decision touches the test tree, the coverage dev-config block, and operator documentation only. Ownership is exactly issue #35's list — `tests/e2e/_prereqs.py`; `tests/e2e/conftest.py` (extensions only — the Signing registry above it is untouched, and the extensions are module-scoped skip fixtures; no service abstractions ship); `tests/e2e/coverage/sitecustomize.py`; `pyproject.toml` (`[tool.coverage]` run/report: `source=src/ranex`, `parallel=true`, fail-under threshold); `README.md` (one documented full-suite entrypoint section); and the two contract tests, spelled here by path: `tests/contract/test_real_suite_entrypoint.py` and `tests/contract/test_prereq_gates.py` — issue #35's exact ownership; neither exists on disk yet and both freeze red at SPEC PRD before implementation. Golden conventions live at `tests/e2e/expected/` with per-family files owned by their family slices; no per-feature real tests land in this slice.

## Scope and threat delta

The frame governs how real e2e tests declare journeys and how their proof is captured; it changes no verdict semantics, gate-catalog meaning, or journal trust rule, and adds no kernel code path. STRIDE: none moved — the disclosure surface it touches is the artifact (transcript plus coverage report), which carries suite output and line numbers only and lives under the ignored `.local/ranex-e2e/` home; the entrypoint never logs env values, keys, or tokens, and inherits ADR-031's rule that trace variables never reach governed or observed commands. Explicit non-goals: harness-lane effect admission (milestone 3) and CI hosting policy (tracker #33 Phase 2); an attacker controlling the artifact path is out of scope — the path is operator-supplied and probed for writability, not trusted for content.

## Quality attributes

| characteristic | scenario | measure |
|---|---|---|
| Determinism | identical runs of one family journey | normalized transcript diffs clean against the golden, byte-exact, run over run |
| Discriminating power | any golden's expected bytes mutated | comparator diffs dirty and names the first differing hunk — red control frozen per golden |
| Skip honesty | a probe's precondition absent versus present; a declared reason paired with its observed skip message | skip reason fires exactly on absence; the declared reason and the observed message are the same bytes — drift is a finding naming both strings; a probe-backed declared-but-not-observed skip exits the entrypoint nonzero, a context-bound one is reported informational |
| Hook reachability | any child environment the frame wires, vendored-clone wiring included | hook dir appended to the child PYTHONPATH, coverage env absolute, data file in the one shared ignored home |
| Coverage truth | a measured subprocess child versus a frame-wired hookless child | per-file line/branch numbers reported; the latter fails loudly, never fake zero; unwired children report unmeasured |
| Reproducibility | entrypoint rerun at the same commit | repeated `coverage combine --keep` over retained inputs reproduces identical data and report, artifact teed, duration within the README's stated budget |

## Reversibility

Door: two-way

The frame is test-tree tooling and documentation: removing the entrypoint section, the probes, the sitecustomize hook, and the coverage block leaves the kernel, the journal, and every existing frozen test byte-identical; the `.local/ranex-e2e/` artifact home is ignored and swept, so retiring the frame leaves no residue in a committed tree. Once family goldens exist under `tests/e2e/expected/` and a fail-under number is recorded, retiring the frame means retiring those goldens deliberately — a visible slice, never a silent patch.

## Sad paths

- 1. Entry run on an unqualified host → the `qualified_host` probe returns (False, named reason); the skip is recorded with its machine-greppable reason, the entrypoint exits nonzero if the skip is undeclared in the manifest — never a silent green.
- 2. Coverage data missing for a SIGKILLed child → reported as an accounted gap in the coverage annotation; never guessed, never imputed; the fail-under threshold absorbs the documented blind spot.
- 3. Golden mismatch → the exact unified diff of the first differing hunk in the failure output, no truncation, the family named — never a bare "assert False".
- 4. Artifact path unwritable → loud failure before the run starts (pre-run writability probe), no partial run, no swallowed tee error mid-run.
- 5.
