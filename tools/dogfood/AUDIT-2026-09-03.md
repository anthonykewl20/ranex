# Dogfood suite audit — 2026-09-03

Full adversarial audit of `tools/dogfood/**` (dogfood.py, scenarios.py, the three
proof modules, benchmarks.py, both report sites, and the oss_bench harness) with
one goal: enumerate every blind spot that lets a bug, edge case, sad path, or
gaming attempt pass unnoticed. Method, in the order evidence was gathered:

1. **Control-flow / path coverage** — AST cyclomatic complexity of the judged
   kernel core; branch coverage of the kernel under the dogfood suite.
2. **Combinatorics** — full input-space enumeration of the kernel entry points
   the dogfood claims to train (claims × evidence × suite results).
3. **Boundary-value analysis** — equivalence classes at domain edges
   (exit codes, unicode, 2^53, base64 spellings, digest charsets).
4. **Mutation testing** — 18 hand-designed semantic mutants against the kernel,
   full dogfood run per mutant, in-place with restore. 7/18 killed (39%).
5. **Boolean algebra / information theory** — exhaustiveness claims checked
   against actual truth-table domains; the journal's detection power derived
   from its structure (no external anchor ⇒ partial-edit detection only), then
   proven by PoC.
6. **Exact statistics** — Clopper-Pearson bounds on the benchmark's
   "0 false verdicts" claims; power analysis.

Everything below was executed against the working tree at commit `d4d640a33`
(+ then-dirty `oss_report_site.py`); nothing in this audit modified the repo.
**Note:** the repo's unattended loop landed commits `b40fe84dd` and `7e7edcb39`
*mid-audit* (the dirty file was committed and reworked); section E-01 was
re-verified against HEAD and updated accordingly. Baseline state:
`dogfood.py run` = **33/33 PASS in ~10s** (README says 32).

## A. CRITICAL — journal threat model: the chain detects only partial edits

**A-01 Full-rewrite forgery is undetectable.** The chain is
`link_i = sha256(canonical({prev_link, record_i}))` rooted at a public genesis
(`journal.py:18`). There is no commitment of the head outside the mutable
database — no signed checkpoint, no external anchor. Information-theoretically
a hash chain over rows an attacker can rewrite in full is equivalent to a
linked list the attacker can rebuild. Proven by PoC:

```
intact verify: True
(A) full-rewrite forge -> verify(): True | head verdict now: PASS
```

With the UPDATE/DELETE triggers dropped — a capability the dogfood itself
demonstrates (`journal-tamper-detected`) — every FAIL verdict in a 5-row
journal was rewritten to PASS, all links recomputed, and `verify()` returned
True. The dogfood proves detection of a *single-row* edit and never states or
tests the boundary of that guarantee. For an "enterprise deterministic judge"
this is the highest-severity gap in the suite: the tamper scenarios certify
less than they appear to.

**A-02 Tail truncation is undetectable.** Deleting the last k rows leaves a
consistent chain prefix: `verify() → True`, `head()` silently moves back. An
attacker (or a buggy GC) can delete every unfavorable verdict and the chain
reports clean. PoC: 5 rows → deleted seq≥4 → `verify(): True`, 3 rows remain.
`append_if_head` CAS only notices if a caller holds a pre-deletion head.

**A-03 `verify()` prev_link continuity is dogfood-invisible (mutant M10
survived).** Disabling `if row["prev_link"] != prev_link` (journal.py:171)
changes no scenario outcome. Combined with A-02: a spliced chain (prefix of
journal A + suffix of journal B, links recomputed per row) verifies — no
scenario constructs a wrong-prev/right-link row. Coverage confirms line 171
cold.

*Fix directions:* sign the chain head (verdict_signing exists in the kernel)
or anchor it in the evidence/governance layer; add dogfood scenarios for
full-rewrite, truncation, and splice; make `verify()`'s documented contract
state exactly what it detects.

## B. HIGH — blind spots proven by surviving mutants (each is a one-line kernel change the green suite accepted)

All 18 mutants, protocol, and per-mutant killer detail are in
`/tmp/ranex-audit/mutation_results3.json`. Controls validated the method:
M02 (contradiction off), M03 (self-approval off), M05 (duplicate claims
allowed), M07 (unknown producer trusted), M11 (chain rule drops prev_link),
M12 (failed tests map to "passed"), M13 (considered unsorted) were each killed
by exactly the scenario designed to kill them. The survivors:

| Mut | One-line change | Survives because |
|---|---|---|
| **M04** | `satisfies()` stops checking `missing ∩ expected_ids` | **The entire results_required machinery (verdict.py:143–162) and `suite_diagnosis` (167–190) have 0% dogfood coverage.** The flagship anti-goalpost-moving property proven in the divergence demo is exercised only through the oss_bench e2e path, never pinned at kernel level. 0/896 input classes. |
| **M09** | `canonical_json`: `ensure_ascii=False → True` | The "independent implementation agreement" proof samples pure ASCII only. Empirically, kernel vs independent disagree on every non-ASCII string (`'café'` → raw UTF-8 vs `\u00e9`). The agreement theorem is false over the actual input domain; the proof just never samples it. |
| **M01** | `exit_code != 0` → `exit_code > 0` | No scenario pins negative exit codes. A test command killed by a signal (Python subprocess gives −9) would count as *success* under this mutant. Boundary class {−1, −9, 255, 256} unpinned. |
| **M06** | admission closed-field-set check disabled | The documented order (extra-field rejected *before* signature verify — an anti-forgery decision argued at length in admission.py:425-438) is unpinned. Coverage 27%. |
| **M15** | `is_signature` rejection skipped | MALFORMED_SIGNATURE vs BAD_SIGNATURE taxonomy distinction unpinned. |
| **M08** | base64 canonical re-encode check disabled | The key-alias attack defense (signing.py:88-98, four spellings of a public key) has zero scenarios. Coverage confirms line 95 cold. |
| **M17** | digest regex accepts uppercase hex | Digest charset boundary unpinned — `sha256:ABC…` would become a valid claim/evidence digest. |
| **M18** | duplicate junit test-ID refusal disabled | suite_results.py:186 cold. A duplicated `tests/foo.py::test_x` (parametrize collision, conftest weirdness) would silently collapse two outcomes. |
| **M14** | `_test_id` drops the `"tests"`-prefix normalization | Not only unpinned — the only real-pytest scenario (`suite-freeze-drift`) places its test file at the scratch *root*, where the branch is dead code by construction. The ID-synthesis rule that shapes every real suite manifest is invisible to the suite. |
| M16 | `command_digest` reverses argv | *Equivalent mutant* (reversal is a bijection; order-sensitivity is preserved) — but it exposes a real gap: **no scenario pins a fixed digest constant**, so any canonicalization drift silently invalidates every committed governance claim while the suite stays green (internal consistency is all it checks). |

## B'. HIGH — the canonical-JSON disagreement is also a latent false-alarm bomb

`dogfood.py:44-46` (`canonical_bytes`, `ensure_ascii=True`) and
`math_proofs._independent_canonical` (json.dumps default `ensure_ascii=True`)
diverge from the kernel (`canonical.py:14`, `ensure_ascii=False`). Two
consequences: (a) the agreement proof is vacuous for non-ASCII (M09); (b) the
day a journal record legitimately contains a non-ASCII approver or reason
string, `proof-journal-chain-algebra` and `proof-manifest-digest` will
**false-FAIL** — the independent recomputation no longer models the kernel.
The independent implementations must mirror kernel semantics exactly, or the
proofs should pin non-ASCII refusal — today the kernel *accepts* non-ASCII, so
mirror it.

## C. HIGH — oss_bench harness (bugs that fired in production data)

**C-01 The `argv[3]` positional cmd parsing fired for real.**
`run_divergence.py:83` assumes every VulcanBench test cmd is
`python -m pytest <node>` and takes `shlex.split(cmd)[3]`. The recorded run
`legacy-blendcore-binary-parity-6e7fa51f` produced
`… --junitxml=… pytest pytest pytest pytest pytest pytest pytest pytest pytest`
— nine literal "pytest" strings as node IDs, pytest errored
(`file or directory not found: pytest`, exit 4). The gate FAILed for the
wrong reason and *coincidentally* agreed with ground truth 0.0, so the row is
counted in "gate agrees everywhere". On a solved task with that cmd shape the
same bug manufactures a **false block**. No assertion validates the cmd shape.

**C-02 `self_report` regex has a negation blind spot — and it is published
data.** The heuristic marks these `claimed_success=True` (all verified):
"This is not fixed yet, still failing." / "Not done: three tests still fail." /
"Nothing is fixed; all tests fail." / "I have not implemented the retry path."
Every negated failure sentence matches (`fixed`, `done\b`, `implemented` have
no negation handling). The six recorded runs happened to agree with truth, but
the mechanism is systematically biased exactly on the sentences that matter.
The page's "agent claims" column inherits this.

**C-03 No incremental persistence.** `run_divergence.py` and
`run_baseline.py` accumulate rows in memory and write the report only at the
end. Any uncaught exception — `TimeoutExpired` (3600s cap), `KeyError` on
summary shape, `IndexError` on `api_key_file_line`, `IsADirectoryError` when a
task's `tests/` has subdirectories (`copy2` in `build_manifest_governed_repo`,
unlike `two_arm.py` which handles dirs) — destroys every already-paid-for row.
For a paid-API experiment this is an expensive sad path. Only `AssertionError`
is caught per-row.

**C-14-style global temp path.** `/tmp/freeze-probe.xml`
(run_divergence.py:87-90) is a fixed shared path: concurrent runs collide; if
pytest dies before writing junitxml, `read_bytes()` reads the *previous
task's* file and freezes a manifest over the wrong suite, silently.

**C-04 Budget cap not enforced.** `state.json` carries `budget_cap_usd: 5.0`,
but `run_baseline.py`/`run_divergence.py` never read it — only `--per-run-cap`
(default $1) is passed to vulcanbench, and there is no cross-task total.
Six fresh divergence runs can spend $6+ against a $5 declared cap. (Observed:
the legacy run alone cost $1.0137 — 1.4% *over* its own $1 cap.)

**C-05 Verdict parsing by prose substring.** `two_arm.py:179,182`:
`gate_pass = returncode == 0 and "FAIL" not in stdout`;
`journal_ok = returncode == 0 and "verified" in stdout`. Both are redundant
with the exit code today (CLI prints `PASS … chain=verified` / `FAIL …
chain=invalid`) but couple the harness to wording: any prose change, or an
attacker-influenced identifier containing "FAIL", flips the recorded verdict.
Parse exit codes, or match the exact `PASS `/`FAIL ` line heads.

**C-06 Bare-arm asymmetry.** In `mode_tasks`, the gold arm runs all entries
cumulatively on one patched tree; the empty arm re-clones before *every* entry.
Test-ordering/state effects make the arms non-comparable and the ground truth
asymmetric by construction (dead third tuple element in `targets` shows the
intent was never finished).

## D. MEDIUM — statistics: the agreement claims are underpowered as stated

"Divergence … gate agrees with hidden tests everywhere (0 false passes, 0
false blocks)" (commit message and page) from **6 runs over 4 distinct tasks**
(2 tasks run twice):

- Exact one-sided 95% Clopper-Pearson upper bound on the false-pass rate:
  **39.3%** (n=6); **52.7%** using distinct tasks (n=4); baseline (n=3):
  63.2%. Rule-of-three approximations: 0.50 / 0.75 / 1.00.
- Power: if the true false-pass rate were 20%, P(observing 0 in 6) = 0.26; at
  30%, 0.12. The study as run cannot distinguish a 20% false-pass rate from
  zero.
- The 6 runs are clustered (same model, same 3 mini-task families + 1 legacy);
  they are not 6 independent draws, so even the n=6 bound is optimistic.
- All tasks are binary (1.0 or 0.0); "agreement" is undefined for partial
  scores, and no partially-solved task was ever tested.

This is not a request for bigger marketing numbers — it is a request to state
the interval next to the claim (the page currently prints "0" with no n-derived
uncertainty), or to run the ~60–100 tasks the claim would actually need.

## E. MEDIUM — report sites: hardcoded numbers that contradict their own receipts

**E-01 `oss_report_site.py` — found on the pre-commit working tree, partially
repaired mid-audit.** Against the working-tree snapshot the docstring's
promise ("Every number in layer 1 is the same number layer 2 proves. Nothing
is decorative data.") was violated concretely: a hardcoded "7–12s" cost stat
contradicting the 1.2–1.4s receipts (with the data-derived `overhead` variable
computed and never used), a checklist SVG naming a test that does not exist
(`test_keys_reflects_txn`), dead `DELETED_TESTS`/`KEPT_TESTS` constants and a
dead `bubble()` helper with a broken placeholder, and `_esc(value: any)`
annotated with the builtin. **Status at HEAD (`7e7edcb39`): the unattended
loop's commits fixed all of these** — `Any`, no hardcoded test names, stats
templated (`FPASSES`/`FBLOCKS`/`CAUGHT/ATTACKS`) from the data. Remaining at
HEAD: the "ms to re-verify" stat still carries no derived number, and the
layer-1-vs-receipts equality is still enforced only by convention, not by the
renderer. Keep this finding as the standing risk class: any hand-typed
number in a page whose footer says "nothing here was typed by hand" is a
self-inflicted integrity wound; derive every visible number from the JSON or
delete it.

**E-02 `report_site.py` claims "6 of 6 cheat attempts are caught" as
`len(CHEAT_ATTEMPTS)`** — a constant, not a result. `cmd_report` writes the
page even when scenarios fail (exit 1), so a failing tamper scenario would
leave the page asserting all cheats caught while the proof board on the same
page shows the failure. The cheat list is also mapped to scenarios by comment
only — nothing verifies the mapping at render time.

**E-03 `cmd_report` runs each scenario once** (`dogfood.py:371`) yet the page
says "N/33 deterministic proofs pass" and "everything deterministic is checked
twice, nightly". The double-run determinism check exists only in
`run`/`iterate`. Also: the fingerprinted JSON embeds `generated_utc`, so the
sha256 fingerprint changes between two content-identical renders (it verifies
page↔data pairing, not content stability — the page text oversells it); and
the command rewrites README, contradicting the module docstring "Nothing here
mutates the working tree".

## F. LOW — dogfood.py mechanical edges

- **F-01** `bench --repeat 0` / negative → unhandled `StatisticsError` (no
  argparse bound). Same empty-sample crash class in `benchmarks.Metric`.
- **F-02** Baseline rows are never garbage-collected: deleting a scenario
  leaves its digest in `baselines.json` forever (only iteration-diff has
  GONE). Re-adding an id with different facts misreports as drift.
  `unbaselined` findings don't affect the exit code, so a never-baselined new
  scenario is invisible to automation.
- **F-03** `write_iteration` numbering = `len(existing)+1`: two concurrent
  runs take the same number (overwrite, no lock); lexicographic sort breaks at
  iteration-1000 (`iteration-1000` sorts before `iteration-101`); ledger files
  are loaded with no schema validation.
- **F-04** The determinism check runs both executions **in one process** —
  module-global state (lru_caches, import order, monkeypatched seams) is
  shared, so process-level nondeterminism passes the check. Two subprocess
  runs would match the claim. `execute_with_determinism_check`'s `scratch`
  parameter is dead.
- **F-05** `keygen-refuses-repo-paths` probes a repo-internal path with no
  cleanup guard: if the kernel ever regresses and writes the key, the
  assertion fails forever after (file persists in the working tree) and a
  private-key file leaks into the repo. Guard with try/finally-unlink.
- **F-06** Doc rot: README says "Curriculum (32 scenarios)", actual 33;
  `signing.py` docstring says "exactly seven"/"eight" signed fields — the
  tuple has 10; `check_release.py` comment says "or newer" but a version
  rollback (benched > current) exits 3 BENCH-READY instead of 0.
- **F-07** `real-subject-digest-binding` asserts `HEAD != HEAD~1` tree digests:
  an empty commit between them makes the scenario fail (history-shape
  coupling, false positive).
- **F-08** Divergence data quality: `final_words` carries mojibake
  (`\u00e2\u0080\u0094`) rendered verbatim on the page.
- **F-09** `cmd_bench` imports `time` inside the loop (shadowed, dead).

## What the suite genuinely proves (keep)

To be as precise about the teeth as about the gaps: contradiction-blocking,
self-approval refusal, absence-blocking, duplicate-claim precondition,
unknown-producer rejection, the journal chain rule (via independent hashlib
recomputation — killed mutant M11 that the plain scenarios alone would have
missed), failed-test → non_passed mapping over real pytest, permutation
invariance, and order-sensitivity-of-command-digests are all real, and each
killed its targeted mutant exactly. The two-layer design (kernel scenario +
independent math recomputation) is the right idea; it is just applied to 4 of
the 6 core modules' worth of paths.

## Recommended repair order

1. Journal: sign/anchor the chain head; add full-rewrite, truncation, and
   splice scenarios (A-01/02/03). Until then, reword every "tamper-evident"
   claim to "partial-edit-evident".
2. Add kernel-level results_required scenarios (M04): manifest match/mismatch,
   missing IDs, expected skips, xpassed/failed/extra, suite_diagnosis wording —
   the 896-cell grid reduces to ~12 equivalence classes.
3. Fix the independent canonical implementations to mirror `ensure_ascii=False`
   and add non-ASCII agreement samples (M09 + B').
4. Pin: negative exit codes, digest charset, duplicate test IDs, base64
   canonical spelling, admission rejection taxonomy, a fixed command-digest
   constant, and run suite-freeze-drift from a `tests/` subdirectory (M01,
   M17, M18, M08, M06/M15, M16, M14).
5. oss_bench: assert the cmd shape before `argv[3]` (C-01), fix the
   self-report regex or label it unreliable (C-02), persist rows incrementally
   (C-03), mktemp the freeze probe (C-14), enforce the total budget (C-04),
   parse exit codes not prose (C-05).
6. Pages: derive every layer-1 number from the JSON or delete it (E-01/02);
   make `cmd_report` double-run scenarios before printing "deterministic"
   (E-03); print CI bounds next to "0 false passes" (D).
