# Prior-art sweep D — report

Evidence date: 2026-07-30. All version/maintenance facts below were pulled live from the GitHub API, PyPI, or vendor docs during this sweep, not recalled. Nothing in the repository was modified.

## Provision verdicts

### `CONT-GENERATE-001` — **REPLACE**

This is `cog`, exactly, and it has been solved since ~2004. **cog** (nedbat/cog, `cogapp` 3.6.0 on PyPI, MIT, repo pushed 2026-07-30 — literally today) generates output into marked spans inside any text file, and its CLI (verified from `docs/running.rst` in the repo) provides precisely the three things the draft specifies from scratch:

- `--check` — "Check that the files would not change if run again … useful in continuous integration" → the drift check.
- `--check-fail-msg MSG` and `--diff` — actionable CI failure output.
- `-c` — checksums the generated output "to protect it against accidental change" → the draft's "never-hand-edit rule" for generated regions, enforced mechanically rather than by convention.

cog is Python, so `generate_contracts.py` calls into it (or is invoked *by* cog snippets) with no new language in the toolchain. The draft's marker format, span-emission machinery, and byte-for-byte recomputation logic should all be **deleted**; the only thing left to write is the small functions that compute the counts — which is the payload, not the mechanism.

Alternatives verified and rejected: `markdown-magic` (MIT, 4.11.0, 2026-06-29, active — but JS, weaker check story), `embedme` (MIT, last push **2024-10-06** — stale, code-snippet-specific), `doctoc` (MIT, v2.5.0, active — TOC-only), `terraform-docs` (MIT, v0.24.0, active, has `--output-check`, verified in its reference docs — but Terraform-specific; its `--output-check` flag is useful *as evidence that check-mode-in-CI is the established convention*), `helm-docs` (**GPL-3.0**, active — chart-specific, licence-flagged).

### `CONT-DRIFT-001` — **ADOPT-PARTIAL**

- **Tier 1 (generated spans)** is solved: it is `cog --check` wired into `validate_contracts.py` and CI. Delete the bespoke "drift check class" spec for this tier; it becomes one subprocess call and a non-zero exit code. The "no waiver" property is a *policy decision about how you wire it*, not a tool feature — no tool can stop a future maintainer adding a skip flag; only review and the server-side check (below) do that.
- **Tier 2 (authored-but-recomputable claims)** — no general-purpose public tool verified for "assert this prose number equals this computed value." Doctest-family tools (Python doctest, mdBook's Rust doctests — MPL-2.0, active) verify *executable examples*, not arbitrary numeric claims; `doc-detective` does docs-as-tests for UI/procedures but is **AGPL-3.0** (flag: avoid) and small (127 stars). **However**: the honest finding is that tier 2 should mostly be **dissolved, not built** — any claim expressible in the draft's "extractable form" can instead be moved *inside* a cog span, at which point tier 1 covers it. The residue is only claims that must remain prose for editorial reasons; run the census the draft already calls for before building anything.
- **Tier 3 (link/reference hygiene)** is solved by `lychee` (Apache-2.0, v0.24.2, 2026-05-01, active, 3.8k stars); `markdown-link-check` (ISC, active) is the smaller alternative.

### `CONT-SESSION-001` — **ADOPT-PARTIAL** (the only provision with genuine residue)

Three findings, in decreasing solvedness:

1. **Agent instruction files are a settled standard: adopt `AGENTS.md`.** Verified at [agents.md](https://agents.md/): used by 60k+ open-source repositories, supported by Codex, Cursor, Amp, Jules, Copilot coding agent, Devin, Aider, opencode, Zed, Warp, Windsurf, Gemini CLI and more, and now **stewarded by the Agentic AI Foundation under the Linux Foundation**. `CLAUDE.md` and `.cursorrules` are vendor-specific predecessors; `AGENTS.md` is the convergence point. But note its scope: it is a *README for agents* — durable instructions, not session state. It does not do what `CONT-SESSION-001` wants.
2. **Memory products do not fit and should not be adopted for this.** `mem0` (Apache-2.0, 62k stars, active), `Letta` (Apache-2.0, 24k stars, active), `Zep` (Apache-2.0, active), LangGraph checkpointing (MIT, 1.2.10, 2026-07-28), and the MCP reference memory server (MIT→Apache-2.0 transition per its LICENSE) are all alive and adopted — and all solve *conversational/semantic memory via retrieval*, which is nondeterministic and service-backed. The draft's requirements (deterministic, zero-token, commit-pinned, stale-by-construction) exclude the entire category. This is a KEEP-shaped search result for the artifact itself.
3. **No public standard exists for a commit-pinned project-state handoff artifact.** Searched: agents.md FAQ and ecosystem, memory products above, Claude Code's native session persistence (resume/compaction — harness-specific, not commit-pinned, not inspectable as a repo artifact). Community `HANDOFF.md`-style patterns exist but no schema has converged. **The authored fixed-field list is real residue.** Two amendments: (a) the *generated* section should not get bespoke machinery — it is a cog projection like everything else in `CONT-GENERATE-001`, so delete that machinery from this provision; (b) don't invent field names cold — PagerDuty's published incident-response handoff vocabulary, the **CAN report** (Condition / Actions / Needs, verified at [response.pagerduty.com](https://response.pagerduty.com/before/different_roles/)), is the closest published software-engineering analog to I-PASS and its terms map cleanly onto the draft's "blocked items / next action / what must not be retried" fields.

### `CONT-TRIPWIRE-001` — **REPLACE** (all four layers are existing-tool configuration)

The layered *analysis* in the draft is correct and honest — but every layer already has a named, maintained implementation, so the provision reduces from "design" to "configuration choices":

1. **In-validator** → `cog --check` inside `validate_contracts.py` (see above). Nothing to design.
2. **Harness session hook** → **Claude Code hooks**, verified at [docs.anthropic.com hooks reference](https://docs.anthropic.com/en/docs/claude-code/hooks): `SessionEnd` and `Stop` are first-class documented events; command hooks are deterministic shell scripts executed by the harness, not the model. **This also settles the draft's Unknown 1**, in both directions: hooks in `.claude/settings.json` are repo files the agent can edit (weak), but hooks delivered via **managed policy settings** are admin-controlled, merge additively, and per the docs "the `disableAllHooks` setting can't disable managed hooks from outside managed settings," with `allowManagedHooksOnly` available to block user/project/plugin hooks entirely. A managed-policy `SessionEnd`/`Stop` hook is genuinely outside the governed agent's write surface.
3. **Git pre-commit** → the **pre-commit framework** (MIT, v4.6.1, 2026-07-21, 15.5k stars) or **lefthook** (MIT, v2.1.10, 2026-07-08, 8.6k stars, Evil Martians). `husky` (MIT, 35k stars, last push 2026-03) is Node-centric; pre-commit fits a Python repo. Do not write bespoke hook installers. The draft's caveat (`--no-verify`, hook deletion) is accurate for all of them.
4. **Server-side required check** → **GitHub branch protection / rulesets with required status checks**, verified at [GitHub docs](https://docs.github.com/en/repositories/configuring-branches-and-merges-in-your-repository/managing-protected-branches/about-protected-branches): required checks must pass before merge; "Do not allow bypassing the above settings" extends enforcement to admins; you can pin a required check to a specific GitHub App as its only accepted source. **danger-js** (MIT, 13.0.10, 2026-06-25, 5.5k stars, "stop saying 'you forgot to…'") is the right vehicle for the PR-level rule "continuity artifact exists and is pinned to this PR's head commit" — a ~10-line Dangerfile, run in CI, made a required check.

**Which mechanisms are genuinely non-bypassable** (the task's specific question): only layer 4, and only against a party without GitHub repo-settings access. An agent with local write access defeats layers 1–3 (edit validator / edit `.claude/settings.json` / `--no-verify`); managed-policy Claude Code hooks defeat the agent but not the operator; branch protection with required checks and no-bypass defeats everyone except whoever holds admin on GitHub — and in a solo-owner repo, that owner. Layers 1–3 catch honest omission only. The draft already says exactly this; it should keep the honesty and delete the mechanisms.
