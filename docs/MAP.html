The simplest summary of how it all works

One paragraph, then the loop.

You run AI agents that write software. An agent cannot see whether its own work actually landed, so it reports success either way — and most tooling lets the same actor write the code, write the test, and declare victory. Ranex never reads the agent's report. It fixes the target before the work starts, re-runs the checks itself against a fresh sealed copy of the code, signs what it observed, and stamps the result into a tamper-evident record. A part ships only when the traveler is stamped. Ranex does not make the agent's code better — it makes misses visible and cheap, and hits provable.

1. SPECIFY what "done" looks like, written as executable checks 2. FREEZE the checks are digested and made read-only to the agent 3. EXECUTE the agent works; its summary is discarded, the diff on disk is read 4. MEASURE Ranex re-runs the bound command itself, in a sealed environment, against a fresh copy of the exact commit — never the agent's word 5. RECORD exit code + code digest signed, checked against the frozen target, appended to a hash-chained journal 6. APPROVE only by someone who did not produce the work — absence blocks, contradiction blocks, self-approval blocks

Factory language, because it is the same idea that solved this before: the go/no-go gauge (frozen tests), the traveler (the journal — an unstamped part does not ship), poka-yoke (the agent cannot edit its own test), and the andon cord (three misses stops the line and asks the owner a product question, in plain language). The models and harnesses are the machine tools — bought, swappable, not Ranex's problem. Ranex is the quality system around them.

Proven — built, tested, and carrying executed evidence

Each item below is proven by tests that pass on disk today — and each row says what it does not cover, because a proven gauge with unnamed holes is a brochure.

ProvenDeterministic verdict kernel

A pure function of (gate, evidence, subject, approver). Same inputs, same verdict, always. No model is consulted; removing every model credential from the machine changes no verdict.

Does not cover: the approver is an unauthenticated string (RISK-07).

ProvenSubject-bound evidence

Every result is welded to the exact code digest it measured. Run the same command against a different commit and the old result stops counting automatically.

ProvenEvidence authenticity

Every record carries an Ed25519 signature, verified against a keyring read from the commit itself — never from the working tree, which an attacker could name.

Does not cover: the measured party can currently reach the signing key (RISK-06).

ProvenClaim↔command binding

The catalog declares the exact command that satisfies each claim, and the kernel compares digests — so a signed record of true can never satisfy tests-executed. Six independent audits failed to break this binding.

ProvenHermetic observation

The command runs against a fresh materialisation of the committed tree (every blob checked), in an environment built from empty, with a pinned toolchain. The agent brings nothing: no ingredients, no scale, no kitchen of its own.

Does not cover: trees needing installed dependencies, or carrying symlinks/submodules, cannot be observed at all (deliberately withdrawn).

ProvenAppend-only hash-chained journal

Every verdict is stamped into a SQLite journal that rejects updates and deletes at the database level, with a hash chain that exposes any out-of-band row edit. ranex journal verify recomputes the chain.

Does not cover: chopping off the tail (rollback/truncation) is not detected (RISK-19); evidence.json is not append-only (RISK-11).

ProvenPath confinement & dirty-tree refusal

Ranex refuses to run if the worktree differs from HEAD, and every path it touches is confined to the repository.

Does not cover: HOME is still inherited by Ranex's own git queries (RISK-13).

ProvenRefusal reporting

A forged or malformed record is reported as refused, with a reason — never silently filed as "no evidence", because an attack and an unfinished task are not the same event.

Does not cover: 44 refusal paths have no test executing them (RISK-09).

ProvenDocs-discipline self-gauge

The repository that once held 561 architecture files and zero product code now has a test-enforced cap on its own documents — the rules govern the rule-maker.

Does not cover: the bill-of-materials checker is structural, not semantic.

ProvenRed-then-green as a fact in git history

The first slice's tests were committed failing, before any implementation existed — the target was drawn before the throw, verifiable in git ancestry.

Does not cover: ancestry is forgeable while history is unsigned (RISK-20).

ProvenMutation census as calibration report

mutmut deliberately broke the code 2,596 ways and recorded which breaks the tests missed: 880 survivors. That number is not a backlog — it is the gauge's own calibration report, published rather than smoothed over.

Does not cover: nothing consumes this result as a gate; no negative controls exist.

Unproven — nothing running behind it yet

Three grades, worst last. The right-hand question on every row: is there mature, world-proven code to copy in (per the adoption rule: copy, improve, own — never add a dependency), or must it be invented?

Decided, unbuilt An ADR stands; no code yet

Landlock confinement of the bound command

So the measured party cannot reach the key that signs its own measurement. ADR-006 accepted; its slice was withdrawn and re-sequenced; the hole is open.

Prior art: mature — Landlock is a shipped Linux kernel ABI; reference code vendored on disk.

Dependency provisioning for gated suites

So a real committed test suite can run inside the sealed environment. Until this lands, Ranex gates nothing — including itself (RISK-08).

Prior art: mature pattern — pip's hash-checking mode, vendored on disk.

Designed, unbuilt Prose exists; never executed

Worker port & dispatch — the single largest untested assumption

Hand an immutable task envelope to an agent in an isolated worktree, then judge the diff on disk. Designed in the pre-reset corpus; never run.

Prior art: split — git worktrees are mature; dispatching an AI harness and judging its diff has no proven implementation anywhere. This is the genuinely novel part.

Budget, three-miss stop, escalation

Bounded spend; after three failures, stop and ask the owner a product question in plain language. The only machinery that would serve "money gone, nothing finished".

Prior art: timeouts and circuit breakers are mature patterns; the three-miss composition is small and novel.

Intake, flow graph, scenario compilation

Plain-language intent → a graph the owner approves → covering paths → scenarios → frozen contract tests. The approved graph is the root of trust.

Prior art: split — BDD/Gherkin and model-based testing cover pieces; the full chain is unproven.

TaskPacket frozen-work envelope · rich verdict vocabulary · independence record · freeze-line machinery

Content-addressed task packet · a diagnostic outcome set beyond PASS/FAIL · recording that evaluator and producer are genuinely distinct · enforcing that the specification is read-only to whoever executes it.

Prior art: content-addressing and CI freezes are mature; the compositions are small or novel.

Vague Not even designed

The translator

The machine state and verdicts have no plain-language projection. This is why "I can't tell what it did" is unserved. It may read; it may never decide.

Prior art: none — a read-only projection of this record is novel.

Production-configuration record

The record must bind the model, harness version, skill and tool manifest, and prompt digest — not the code alone. No design exists.

Prior art: SBOM standards (CycloneDX, SPDX) are mature and directly relevant; not yet consulted.

Outward-facing record · approver authentication · calibration consumption · configuration comparison

A record a distrustful outsider can check · proving the approver is who they claim · turning the mutation census into a gate with negative controls · grading models and harnesses by deliberate experiment rather than confounded logs.

Prior art: certificate transparency solves the first in mature form (cached locally for reading); the rest are mature disciplines with no off-the-shelf tool for this use.

The system-level verdict. Every green card above is a component fact. The loop has never closed around a real agent — nothing Ranex has ever measured was produced by one. So the system as a whole is unproven whatever its components have proven. That is the state, stated without judgment. It is also the owner's named finish line: one complete thread — Idea → Behaviour → Result — before any numbers.

What still needs clarification before a full build

The map names these itself. Seven open decisions — and the interface question, answered.

1. The worker port — how does work reach an agent at all?

The largest untested assumption. CLAUDE.md settles the who (Claude Code, headless, behind a replaceable port) but not the how: envelope format, handoff protocol, what "inspect disk" checks first. Needs an ADR before a slice.

2. The journal ADR — deferred and unnumbered

Verify-before-append, never auto-create, and a size checkpoint — the named remedy for the truncation hole. It has no number yet.

3. The translator — undesigned

What it projects, in what words, and the hard rule that it may read but never decide. Until it exists, the record is a diary.

4–6. Three undesigned records

The production-configuration record (what model/harness/skills/prompt produced this work) · approver authentication (a signature-bound human decision) · budget and escalation machinery (the entire defence of C-02).

7. Two viewpoints govern no view

Cost (C-02) and regression (C-03) have declared viewpoints and nothing for them to govern. The map fails its own completeness check on purpose until they exist.

The interface question — CLI and Web UI. The CLI already exists (run, gate evaluate, journal verify, keygen) and is the designed operator surface — local-first, single machine, one human running a team of agents. A Web UI for front-facing users is out of scope by design: the map defers every external audience ("just needs to work for me"), and a hosted surface would only ever be forced by two named things — an outward record others must verify, and fleet-scale measurement. Neither exists yet. The one interface gap that is in scope is not a UI but the translator: plain-language state and escalation inside the operator's own flow, so a non-technical owner can act without reading code. If a Web UI is wanted anyway, that is an owner decision that overturns local-first — and it should be made knowingly, not drifted into.
The scheduled path, for context. SLICE-006 (make Ranex gate this repository's own test suite) → confinement (ADR-006) → the first complete thread, Idea → Behaviour → Result, with the operator running the agent himself. No new architecture before that thread exists — that is the owner's own sequencing.

What Ranex never claims: it does not improve the quality of generated code, by any margin. "Deterministic" describes the process and the verdict — never the code an agent writes. Anyone claiming an LLM produces identical software twice is selling something.
